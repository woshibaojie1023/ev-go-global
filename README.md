## 1. Problem：先打哪个市场，今天怎么回答

中国新能源汽车出海已从「机会主义出口」进入「选择性深耕」阶段。但目标市场决策长期依赖两类材料：咨询公司的宏观报告（看得懂趋势、落不到单一市场的横向比较）与业务团队的内部 PPT（覆盖市场少、口径不统一、难以复用）。

当一个出海负责人真正要回答「下一个市场选谁」时，需要的是把 **15 个候选市场放进同一套口径横向可比**，并且能在一张图上同时看到「市场天花板」和「进入难度」。本工具就是把这个决策过程产品化：**统一口径 → 加权打分 → 排名 / 筛选 → 单国简报与多国对比 → 可导出留档**。

目标用户为车企战略 / 海外事业部门，核心使用场景有两个：桌面上的横向比选会，以及把结论导出为 PDF / CSV / Markdown 带进汇报。

## 2. 约束如何推导出架构

产品约束在立项时就已明确，架构是约束的结果而非技术偏好：

- **要能被任何招聘方 / 业务方零门槛打开** → 纯静态单页，双击 `index.html` 离线可跑，无安装、无构建、无后端。
- **要能带进真实汇报** → 三种导出对应三种下游：打印 PDF（给不看屏的决策者）、CSV（给要二次分析的分析师，BOM 防 Excel 乱码）、Markdown（给文档 / Wiki 协作）。
- **面向多国市场，受众本身跨语言** → 五语言 i18n；叙事字段双语存储、小语种回退英文。
- **地图是叙事主角** → 不用第三方地图服务（有网络依赖且风格不可控），改用 Canvas 2D 手绘点阵世界地图，视觉语言完全自有。

最终技术栈为 **HTML5 + CSS3 + 原生 JavaScript（ES5 风格）+ Canvas 2D + SVG，零运行时依赖、零构建步骤**。

## 3. AI 协作边界（核心）

这是一个 Vibe Coding 项目，但「Vibe」不等于「放手」。我把协作边界划在 **判断与口径归我、样板与脚手架归 AI**：

**本人负责（不可委托的产品判断）**

- 产品定义与目标用户、信息架构（三栏指挥台的信息流）
- 六维模型的维度选取、**权重假设及其理由**、数据口径与来源分级
- 视觉方向（暖纸底 / 墨蓝印刷感 / 翡翠玉信号色）与全部文案的审校
- 交互范式的取舍（tooltip 延迟、Object Constancy、空状态四要素）

**AI 辅助（可委托的执行）**

- Canvas 绘制样板、碰撞松弛算法、i18n 数据结构脚手架、打印 CSS 骨架

**两个「AI 方案被我否决 / 修正」的实例**：

1. **气泡遮挡**：AI 初版按经纬度直接落子，泰国、越南等密集区气泡互相压住、标签与气泡脱节。AI 给出的方案是「缩小半径统一避让」，但这会牺牲得分的面积编码。我改为 **保留半径编码 + 多轮碰撞松弛（仅做位移、不改大小）+ 描边与标签归属**，信息编码不丢失，可读性问题也解决了。
2. **打印排版**：AI 初版直接把屏幕三栏 `display:block` 化交给浏览器，结果雷达被拦腰截断、导出按钮也被打出来。我重做为 **独立的打印报告 DOM（封面 / 对比段 / 单国段 / 排名表 / 来源声明）+ `@page` 边距 + 分页控制 + 屏幕元素打印隐藏**，并给封面加了「署名仅在配置后输出」的逻辑，避免占位符穿帮。

## 4. 模型方法论

### 4.1 六维与权重

| 维度 | key | 权重 | 选取理由 |
| --- | --- | --- | --- |
| 市场规模 | marketSize | **25%** | 决定天花板；小盘市场即使政策满分也撑不起出海战略 |
| 政策环境 | policy | 20% | 决定准入，补贴 / 关税 / 本地建厂要求 |
| 竞争格局 | competition | 20% | 决定拿单难度，存量对手与中国品牌份额 |
| 消费者接受度 | acceptance | 15% | 决定转化节奏，EV 渗透与认知 |
| 本地化能力 | localization | 10% | 偏长期，供应链 / 人才 / 合资本钱 |
| 风险控制 | riskControl | 10% | 尾部下行保护，政策反复 / 汇率 / 地缘 |

维度顺序遵循「先看要不要进、再看能不能站稳」的决策链路；权重和为 1，并在雷达轴端、CSV 权重注释行、打印报告三处对读者明示。

### 4.2 公式与边界

```
composite = round( Σ score_k × weight_k )        // 各维度 0–100，综合分四舍五入到整数
```

- 单维得分由公开数据 + 规则映射得到，为保持可解释性，不做黑箱拟合。
- 排名按综合分降序，并列时按市场规模兜底，保证排名稳定。
- **敏感性**：权重是示例性假设。把 marketSize 与 policy 的权重对调，头部排名基本稳定（泰国 / 印尼等高容量市场仍居前），中段 4–8 名会出现 1–2 个位次交换 —— 这正是工具同时输出分项得分条、让读者自行复核的原因。
- 该评分为本项目构建的**示例性评估模型，用于产品演示与方法论展示，不构成投资或商业决策依据**。

## 5. 决策日志

1. **选 Canvas 手绘地图而非地图 SDK**：消除网络依赖、视觉完全自有，代价是自建陆地掩码与投影 —— 对 15 国量级完全划算。
2. **对比模式设 3 国上限**：超过 3 国后雷达多色叠加不可读，第 4 国加入时给 toast 提示而非静默失败。
3. **雷达切换用 Object Constancy 插值**：以国家 id 绑定顶点，切换时顶点插值变形而非整体闪白；新加入国家从中心长出，降低视觉跳动。
4. **触屏点节点即选中并出常驻卡片**：pointer:coarse 无 hover，强行模拟 hover 只会误触；点空白关闭，符合移动端心智。
5. **署名 / 邮箱用常量配置**：`PROFILE.name` 留空则封面不输出署名行，宁可缺省也不沿用「[ 你的名字 ]」占位符。

## 6. 文件结构与本地运行

刻意保持零构建，仓库即站点：

```
ev-go-global/
├── index.html      # DOM 骨架 + head(meta/favicon/OG)
├── style.css       # 设计令牌、全部样式、响应式与打印
├── app.js          # 状态、Canvas 地图、雷达、交互、三导出、版本探测
├── data.js         # 15 国数据集 + 六维模型与权重
├── landmask.js     # 128 列点阵陆地掩码
├── i18n.js         # 五语言文案
├── version.json    # 数据版本清单（版本/截止日期/更新日志）
├── tools/
│   └── refresh-data.js   # 季度刷新辅助脚本（版本元数据机械更新）
├── .github/workflows/
│   └── quarterly-data-reminder.yml  # 每季度自动建 Issue 提醒刷新
└── assets/         # 截图、OG 图、（可选）简历二维码
```

**本地运行**：直接双击 `index.html`；或起一个静态服务器 `python -m http.server` 后访问。无 `npm install`、无打包。

## 7. 数据更新机制（季度）

数据为人工核对的公开资料，做不到逐笔实时；机制上保证**至少一个季度更新一次**，由三层组成：

1. **版本清单 `version.json`**：记录 `dataVersion`（如 2026Q3）、`dataAsOf` 截止日期、下次计划更新时间与更新日志。
2. **刷新脚本 `tools/refresh-data.js`**：每季度执行一次，自动完成版本元数据的机械更新——`version.json` 递增并追加 changelog、`data.js` 的 `DATA_AS_OF` 五语言日期同步、`index.html` 缓存版本号递增；数值变化部分按脚本输出的人工检查清单核对：

   ```bash
   node tools/refresh-data.js --quarter=2026Q4 --asof=2026-11 --next=2027-03
   ```

3. **定时提醒 `.github/workflows/quarterly-data-reminder.yml`**：每季度首月（1/4/7/10 月）5 号自动创建一条刷新检查清单 Issue，也可在 Actions 页手动触发。

此外，页面加载后会异步探测线上 `version.json`：当用户本地缓存的版本落后于线上时，弹出提示引导刷新（`file://` 本地打开时自动跳过探测）。提交到 GitHub 后 Pages 自动部署，读者通过资源版本号拿到新数据。

## 8. Roadmap 与局限

- **数据**：季度更新机制已建立（见第 7 节）；后续可补自动化数据校验（取值范围 / 权重和断言）。
- **权重**：现为专家假设，理想形态是接入真实出海结果做权重回测 / 校准。
- **交互**：可补自定义权重滑块，让读者即时看到排名对权重的敏感性。
- **协作**：反馈主路径为 GitHub Issues（公开可追踪）；配置真实邮箱后自动开放邮件次路径。
